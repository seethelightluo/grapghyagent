# Why GraphyAgent

> 先看一个真实图规划（example2），再拆分成图的功能展示，并与传统 Claude Code 的顺序拆分与 ReAct 工作流进行对比。

## example2 图规划（原始图）

```
node_1 (Define Univ & Disciplines)
   │
   ▼
node_2 (Collect Rankings Data)
   │
   ▼
node_3 (Validate Data)
   │
   ├──────────────┐
   ▼              ▼
node_4           node_5
(Calc FP Error)  (Gen Statistics)
   │              │
   └──────┬───────┘
          ▼
       node_6
    (Gen TXT Output)
```

## example2 节点拆分（任务与门禁）

- node_1：定义 10 所大学 + 10 个学科（范围定界）
- node_2：收集排名数据（核心数据采集）
- node_3：数据校验（结构完整性 + 去重 + 计数）
- node_4：误差分析（总体排名 vs 学科平均）
- node_5：统计汇总（均值/方差/极值/计数）
- node_6：生成最终 TXT 输出

## GraphyAgent 的“图能力”功能展示

### 1) 图结构把复杂问题拆成可验证子模块
- 每个节点有清晰的输入、输出与 Gate（通过/失败）。
- 可在节点级别复用、回滚、重跑，避免整条链路重复执行。

### 2) 并行化天然友好
- node_4 与 node_5 可并行执行，缩短整体耗时。
- 并行的节点依赖明确，不会发生“推断顺序错误”。

### 3) 上下文干净、噪声可控
- 每个子模块拥有独立 memory；只带入本节点的必要上下文。
- 不把无关历史“拖进来”，减少上下文污染。

### 4) 结果可审计、证据可追溯
- 规划里有验证规则与证据指针，便于审计与复现实验。

## 与传统 Claude Code 顺序拆分 / ReAct 对比

| 维度 | GraphyAgent（图工作流） | 传统 Claude Code（顺序 task） | ReAct（Reason + Act） |
| --- | --- | --- | --- |
| 任务组织 | DAG 图，显式依赖 | 线性顺序 | 迭代循环（推理-行动） |
| 并行能力 | 内建并行节点 | 基本串行 | 依赖提示策略，难稳定并行 |
| 上下文噪声 | 独立 memory，按需注入 | 历史上下文累积 | 多轮推理易噪声上升 |
| 可验证性 | Gate/规则/证据 | 依赖人工检查 | 依赖推理质量 |
| 复杂问题适配 | 高（拆分+校验+复用） | 中（顺序串行） | 中（长链路成本高） |

## 为什么它更适合复杂与并行问题

- **并行结构**：天然支持多节点并行，无需“猜顺序”。
- **上下文隔离**：子模块独立 memory，完整应用本模块上下文空间，避免噪声混入。
- **可验证与可追溯**：节点输出可校验，证据可回溯。
- **可维护**：某个节点失败只需修复该节点，而不是整条链路重跑。

## 适用场景

- 多步骤研究与报告生成
- 需要并行子任务的复杂问题
- 对可验证性和可追溯性要求高的任务链
